# 模块与依赖边界

插件由多个模块组成，每个模块包含 `Public` 和 `Private` 目录。公开头文件定义契约；私有实现细节不得泄漏到公开头文件中。

- Core 模块不得依赖厂商 SDK，也不得依赖具体的托管、认证、存储或后端 Provider。Provider 模块可以依赖 Core。禁止模块之间循环依赖。
- `.Build.cs` 中的公开依赖必须对应公开头文件真正需要的类型。实现依赖应放入私有依赖。不要仅为修复另一模块的缺失包含而把依赖改为公开。
- Provider 边界优先使用 `UE::Nelaric::` 命名空间下的纯 C++ 接口。需要 Blueprint 支持时，另加独立的 Blueprint 适配层；不要强制每个 Provider 实现都使用反射。
- Core 必须与玩法无关。背包、战斗、任务、角色规则、队伍规则和匹配算法属于接入游戏或可选扩展。Core 可以携带不透明的比赛或会话元数据，但不得解释具体玩法策略。
- 高频玩法状态复制使用 UE 原生网络机制。框架服务处理较低频的控制面工作，例如准入、会话、分配、存储、配置、健康检查和管理。

引入新模块时，应在模块文档中说明其职责和直接依赖。新增跨越上述边界的依赖时，必须在 PR 中解释并交由维护者审查。
