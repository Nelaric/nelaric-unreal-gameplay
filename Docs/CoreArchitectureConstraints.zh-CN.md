# 核心架构约束

本文规定 Nelaric Unreal Gameplay 的目标架构。

## 定位与职责边界

Nelaric 为 Unreal Engine 5.6 及以上版本提供可复用的玩法基础。游戏通过 C++ 和 Blueprint 扩展点定义具体规则与内容；框架提供通用的对局流程、目标、计分、玩家生命周期和组合机制，不限定玩法类型。

Nelaric 基于 Unreal Engine 的 Gameplay Framework 和原生网络系统。具体技能、背包、AI、表现和匹配由接入游戏或可选模块实现。Gameplay Ability System、Game Features 和后端服务是可选集成，不是 Core 的前置条件。

## 玩法权威与状态

权威 World 负责规则判定、对局阶段转换、目标和计分结算，以及玩家生命周期。GameMode 承载仅在服务器运行的决策；GameState 和 PlayerState 提供客户端所需状态。玩法定义描述模式及规则，运行状态记录某局对局的进展。客户端负责表现和提交输入，不决定权威结果。

## 支持的运行拓扑

| 拓扑 | 权威端 | 要求 |
| --- | --- | --- |
| 单机 | 本地 World | 无需网络连接或后端即可运行玩法。 |
| 监听服务器 | 主机的服务器 World | 相同规则在权威端执行，状态同步至远程客户端。 |
| 独立服务器 | 无头服务器 World | 相同规则无需本地玩家或表现层即可运行。 |

这些是 Unreal Engine 网络拓扑，不是 Nelaric 的编译期模式。玩法规则不得要求分别实现本地与联机版本。是否接入后端是独立的可选问题；具体集成自行定义启动、身份和信任契约。

## 玩法组合

Core 定义对局阶段、规则判定、目标、计分和玩家生命周期的稳定契约。玩法模式组合这些机制并提供具体策略。公开扩展点按需要支持 C++ 和 Blueprint。Core 不强制使用特定角色类、相机、输入方案、技能系统或资源布局。

## 内容更新

已 Cook 的玩法数据和内容可以按版本独立于基础构建交付。内容版本标明兼容的基础构建、所需资源和激活边界。一局对局在整个生命周期使用同一版本；新内容在下一局或进程启动等明确的安全边界生效。同一联机对局的参与方必须使用兼容的内容和协议版本。

原生 C++ 代码、反射类型布局和网络协议的变更需要兼容的新构建及发布流程。编辑器 Live Coding 属于开发工具，不是运行时内容更新契约。分发渠道和平台专属补丁交付不属于 Core。

## 验收条件

框架应支持在单机、监听服务器和独立服务器会话中制作、测试同一个玩法模式。第一个验收样例是在三种拓扑下运行的目标计分模式；第二种不同的模式应通过公开扩展点实现，而无需修改 Core。内容更新测试应覆盖版本兼容性及规定边界上的激活行为。
